# Crown Telegram bot

Уведомления контент-мейкеру в телегу: донаты, задачи и их дедлайны, лоты аукциона, сборы,
раунды рулетки, выплаты, месячный дайджест. Плюс режим основателей — статистика по платформе.

## Запуск

1. В Telegram открой **@BotFather** → `/newbot` → скопируй токен.
2. Заполни `bot/.env` — **обе** переменные обязательны:

```
TELEGRAM_BOT_TOKEN=123456:ABC-твой-токен
CROWN_BOT_SECRET=<любая длинная строка>
```

`CROWN_BOT_SECRET` должен **совпадать** со значением в `.env.local` сайта. Сервер работает
fail-closed: без совпадающего секрета он отвергает бота целиком (раньше при отсутствии
секрета труба бот↔сервер становилась публичной).

3. Запусти сайт (`npm run dev` или `npm run start`), затем бота.

**Для постоянной работы** — systemd-юнит с автоперезапуском (упавший бот поднимется сам):

```bash
cp bot/crown-bot.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now crown-bot
journalctl --user -u crown-bot -f     # логи
```

Разово, для отладки: `npm run bot`.

Дальше в кабинете: **Settings → Telegram → Connect** — кнопка откроет чат с ботом, жмёшь
Start. Ссылка живёт **15 минут**; просроченную бот распознаёт и просит нажать Connect заново.

## Команды

| Команда | Что делает |
|---|---|
| `/settings` | вкл/выкл категории уведомлений кнопками прямо в чате |
| `/stats` | сегодня и неделя — **реальные суммы из базы** |
| `/monthly` | итог месяца: заработано (и как к прошлому), донаты, лучший день |
| `/help` | что бот умеет |
| `/stop` | отключить |

Категории те же, что в колокольчике на сайте: требует решения · деньги · приятное ·
сводки · проблемы. Месячный дайджест — отдельным переключателем, уходит 1-го числа и
**только если за месяц были донаты** (пустой месяц не тревожат).

## Режим основателей

В чате с ботом: `/founder <секрет>`, где секрет — значение `FOUNDER_SECRET` в `.env.local`
сайта. **Значения по умолчанию нет**: если переменная не задана, режим недоступен (иначе это
был бы угадываемый пароль к платформенной статистике). После входа — `/platform`.

## Как устроено

`bot.mjs` — труба без зависимостей: пересылает апдейты Telegram на `/api/telegram/event`,
забирает очередь из `/api/telegram/outbox` и отчитывается, что реально доставлено. Вся
логика — на стороне сайта (`lib/server/telegram-store.ts`).

**Хранилище — таблицы `tg_*` в основной базе** (`data/crown.db`), а не отдельный файл; её
бэкапит общий механизм (`lib/server/backup.ts`). Файл `bot/data/store.json` остался только
как источник разовой миграции со старой версии.

Доставка **at-least-once**: сайт выдаёт строки «в работе», бот подтверждает то, что Telegram
принял, и лишь тогда они уходят из очереди. Упал бот или Telegram ответил 429 — сообщение
вернётся и уйдёт позже (растущие паузы, до 6 попыток). Если пользователь заблокировал бота,
привязка снимается автоматически.

Курсор Telegram и «лиз» одного инстанса живут в базе: перезапуск продолжает с того же места,
а вторая копия бота сама останавливается вместо двойной доставки.

## Для бэкенда

`POST /api/telegram/notify` `{handle, kind, title, body}` — но это **защищённый** эндпоинт:
нужна подпись владельца страницы или его серверная сессия (`lib/server/auth.ts`,
`authorizeHandleChannel`). Незарегистрированную страницу привязать нельзя.

Игровые события уведомляются автоматически: всё, что проходит через `POST /api/gamestate`,
разбирается в `lib/server/game-notify.ts` — трогать бота для этого не нужно.
