# Cheer — бриф для ИИ-ассистента

Этот файл — вводная для любого ИИ, подключающегося к проекту. Актуален на июль 2026.

## Что это

**Cheer** — dApp донатов для контент-мейкеров (стримеров): страница доната в долларах (USDC) + мини-игры, которыми управляют зрители. Ядро продукта: «Donations you can play». Деньги идут напрямую на кошелёк мейкера (Cheer их не держит), игровые деньги лежат в эскроу до вердикта. $1 доната = 1 очко репутации зрителя у ЭТОГО мейкера (репутация не глобальная).

Терминология: **«content maker»**, не «streamer» (в видимых текстах). Валюта в UI — доллары.

## Стек и структура

- **Next.js 14 App Router**, TypeScript, почти всё — client components ("use client").
- Стили: CSS Modules + токены в `app/globals.css` (`--bg-0..3`, `--text-1..3`, `--accent`, `--accent-grad`, радиусы `--r-*`, анимации `--dur-*`).
- **БД**: libsql/SQLite — `data/cheer.db` (в git НЕ входит). Схема и миграции: `lib/server/db.ts` (append-only массив MIGRATIONS, версия в meta.schema_version).
- **Ончейн**: Solana **devnet** + канистры ICP — это периметр Crown, живущий в соседних клонах
  (`crown-splitter`, `crown-factory`, `crown-indexer`, `crown-relay`, `crown-games/*`). Все id и
  параметры в `lib/chain/config.ts` — копия их профилей (`config/testnet.toml`, `deploy/testnet.toml`);
  `npm run verify:chain` перечитывает те файлы и краснеет на расхождении. Репутация — книга
  `crown-indexer`; пока принципал не настроен, отвечает наш зеркальный `/api/reputation`.
- EVM-код удалён (июль 2026), wagmi нет, адреса — base58 Solana.
- Telegram-бот: `app/api/telegram/*`, локальный стор `bot/`.

## Данные: один источник

**Мок-режима больше нет.** `DataProvider` всегда читает реальное: фид — зеркало
финализованных `Settled`, репутация — книга (или наше зеркало `/api/reputation`, пока принципала
нет), профили — БД. Пусто = пусто, а не сид: экран, способный показать правдоподобное число,
которого никто не заработал, приучает верить и следующему.

Вместе с режимом удалены: демо-создатель (`nova`) и резерв его хендла, вход в кабинет «в демо-режиме»
(и вместе с ним запись профиля **без подписи** — теперь подпись обязательна всегда), демки игр на
`/games/[id]`, `RepDemo`/`DemoDonation` на лендинге, выдуманные метрики админки, сиды очередей
(задачи, круг рулетки, бэкеры сбора) и синтетическое разбиение графика по источникам —
оно теперь считается из самих донатов.

**Прямой донат — две формы, и выбирает их сам донор словами.**

- **Написал имя или сообщение** → форма `direct-settlement`: комиссия 2% **мимо** сплиттера (через
  него она порождала бы `Settled`, то есть репутацию за перевод самим себе), остаток получателю
  **через** сплиттер. Это и оплачивает нашу часть: подпись под донатом, алерт, карточку в Telegram и
  вписывание в книгу. Репутация при этом начисляется с `net`, не с `gross` — витрина обязана говорить
  это теми же словами.
- **Ничего не написал** → голый `donate(gross)`: 0%, всё до цента получателю. Путь первого класса, а
  не лазейка: сплиттер permissionless, так задонатить можно и без нас. Мы просто не даём ничего
  своего — ни текста, ни вписи (`/api/donations/intent` отвечает 402, подающий отказывается платить).

Клиент — `lib/chain/direct.ts` (`buildDirectDonateTx({withFee})` / `buildFreeDonateTx`), числа —
`DS_FEE_BPS`/`DS_MIN_GROSS` в `lib/chain/config.ts` (у самой игры `config/` нет: её спека говорит,
что профиль заводится у клиента, и клиент — это мы). Флор действует только на платную форму:
у бесплатной своего флора нет, и выдумывать его мы не вправе.

## Модель данных и синк

**Профили** (двухслойная):
- Кабинетная копия: `localStorage.cheer-profile` (`ProfileProvider`).
- Серверная: `/api/profiles` (таблица profiles, полный JSON в `data`). Публичные страницы резолвят с сервера.
- **Владение**: кошелёк = логин, паролей нет. Любая запись профиля требует ed25519-подписи
  (`lib/server/auth.ts`, заголовки x-cheer-pubkey/ts/signature, окно ±10 мин) либо сессионной куки,
  полученной за подпись. Страниц без владельца больше не существует — это был единственный путь в
  таблицу профилей, за который никто не отвечал.
- Резолв на публичных страницах игр: `lib/data/usePublicProfile.ts` — свой localStorage →
  GET `/api/profiles/[handle]`. Третьего шага (демо-сид) нет: незарегистрированный хендл резолвится
  в ничто, и это правда.

**Игровые состояния** (общие для всех браузеров):
- Клиентские сторы остаются синхронными читателями localStorage: `lib/data/tasks.ts`, `roulette.ts`, `fundraiser.ts` (ключи вида `cheer-tasks:<scope>` и т.п., scope = handle или сессионный scope).
- Поверх — **синк**: `lib/data/gameSync.ts` (клиент) + `lib/server/gameState.ts` + `/api/gamestate` (сервер, таблица game_state (scope,k)→v).
- Записи идут **операциями**, не блобами: `append` (задание, дедуп по id), `suggest` (дельта пула рулетки по title — одновременные поддержки суммируются), `add` (дельта сбора), `replace` (только авторитетные действия стримера: принять/вернуть/новый раунд/статусы/голоса).
- Страницы монтируют `useGameSync(scope)` — pull на маунте + полл каждые 3с, nonce в deps эффектов чтения. Подключено: 3 публичные страницы игр + их Overview в кабинете.
- Спин рулетки **детерминированный**: `roundRand(startedAt)` (mulberry32) — все браузеры вычисляют одного победителя, гонки нет. Первый взгляд зрителя (`ensureRound`) мету НЕ публикует (share=false), чтобы не сбрасывать часы всем.
- Сервер падает → всё деградирует в старое per-browser поведение, ничего не ломается.

**Сессии игр**: `lib/data/gameSessions.ts` — один мейкер может гонять несколько инстансов игры; scope = ключ сторов; публичный резолв `resolvePublicSession(handle, game, ?s=)`, legacy passthrough на голом handle.

## Контур MVP: что где происходит

Состав первого релиза — периметр + `conditional-tasks` + `conditional-funding` +
`direct-settlement` (прямой донат; у него нет ни канистры, ни своей программы — только форма
транзакции). **Аукцион и подписка удалены из приложения целиком** (2026-08-10): ни страниц, ни
сторов, ни типов, ни принципалов. Их канистры остаются в периметре — вернуть можно, но это будет
новая работа, а не расчехление закомментированного.

Порядок операций одинаков у обеих игр и задан не нами, а периметром (`lib/chain/gameFlows.ts`):

1. **Область (`scope_id`) считается локально** — она коммитит поля будущего эскроу, кроме резолвера.
2. **`get_resolver(scope)`** — бесплатный query; ключ, под которым родится эскроу.
3. **`create_escrow`** — транзакция самого донора (его подпись = его репутация).
4. **Впись рождения** — платная, через `crown-relay`: `POST /api/ingest`. Без неё игра не примет
   регистрацию, а сеттлмент позже упрётся в `UnknownBirth` и репутация вкладчика потеряется.
5. **`push_root`** — платная, через релей: `POST /api/pushroot`. Игра слепа и чейн не читает — она
   ходит по пруфу против корня, который надо ей протолкнуть.
6. **Регистрация** — бесплатный ingress с подписью кошелька + witness рождения из `get_birth`.

Расчёт — зеркально: область решена → `POST /api/verdict` (подпись резолвера; бесплатно, если уже
подписана) → `claim` с ed25519-инструкцией **непосредственно перед** ней → сигнатура сеттлмента тоже
вписывается (он платит через сплиттер, значит попадает в книгу).

**Платные вызовы живут только на сервере** (`lib/server/relay.ts`): ingress не умеет прикреплять
циклы, а релей платит лишь за ключ из своего allowlist (`RELAY_IDENTITY_JSON`, без `NEXT_PUBLIC_`).
Политика подающего — `lib/server/submitter.ts`: потолок ретраев на сигнатуру (журнал в `ingest_jobs`:
счётчик в памяти сбрасывался бы каждым деплоем, то есть его бы не было), свой rate-limit ниже
релейного бюджета, автоматическая обработка `UnknownBirth`.

**Платим только за то, что платит нам.** Рождения и сеттлменты игр — плюс прямой донат, если он
прошёл формой `direct-settlement`, то есть отдал нам комиссию (`logic::payable`, пересчитывается по
готовой транзакции). Донат в 0% мимо нас не вписываем: сплиттер permissionless и этот путь открыт
всем, но платит за него донор со своего бюджета (`00 §9`). Решение принимается **чтением цепи**, а не
полем запроса: подсказка вызывающего — не разрешение.

**Сбор создаётся лениво и в два приёма.** `create_collection` подписывает получатель, но канистра
требует пруф рождения **первого вклада**, которого в этот момент ещё нет. Поэтому подписанное
сообщение лежит у нас (`collection_intents`, `POST /api/collection`) и тратится, когда донор внёс
первый вклад (`POST /api/collection/materialize`).

## Игры (3)

1. **Task for donation** — зритель ставит платное задание (эскроу): pending→active→done/refunded. Конфиг: minAmount, deadlineHours, requireApproval, maxActiveTasks.
2. **Roulette** — зрители предлагают/поддерживают игры донатами, доля пула = шанс; спин по таймеру
   или «Spin now» из кабинета. Режим rank: предлагать бесплатно с тира N. **Деньги настоящие**:
   поддержка идёт обычным донатом (`useCheer().donate`, source `roulette`) — текст предложения и есть
   сообщение, значит форма платная (2%). Колесо двигается только после подтверждённой транзакции.
3. **Fundraiser** — сбор на цель, корона-бейдж (`FundraiserFill`/`CheerBadge`) заливается снизу вверх; вердикт: доставил → деньги его, нет → возврат всем.

У каждой: публичная страница `/@handle/<game>` (вкладки GameTabs: форма/список), билдер-панель и Overview в кабинете, OBS-оверлеи (`/overlay/[handle]/[widget]`).

## Роуты

Страницы: `/` (лендинг), `/discover`, `/games`, `/games/[id]`, `/create` (визард 4 шага), `/space` (кабинет, гейт «кошелёк = логин»), `/admin` (овервью/создатели/донаторы — всё из БД, бот, готовность к запуску), `/privacy`, `/terms`, `/wallet-guide`, `/@handle`, `/@handle/{task,roulette,fundraiser}`, `/@handle/[slug]`, `/overlay/[handle]/[widget]`.

API: `/api/profiles` (+`/[handle]`), `/api/gamestate`, `/api/feed`, `/api/reputation`, `/api/donations/intent`, `/api/indexer` (тест-вставка dev-only + секрет), `/api/texts` (приватные тексты игр — канистры слова не хранят), `/api/health`, `/api/telegram/*`. Рейт-лимиты: `lib/server/ratelimit.ts`.

Платный контур (всё через `crown-relay`, ключ только на сервере): `/api/ingest` (впись сигнатуры),
`/api/pushroot` (корень книги в игру), `/api/verdict` (подпись резолвера), `/api/collection` +
`/api/collection/materialize` (отложенное создание сбора).

## Дизайн-хартия (жёсткая)

- Только тёмная тема. Фон #141318-семейство.
- **Один фиолетовый акцент**: градиент `--accent-grad` (#8B7CF6 → #F4F2FE, сверху вниз), flat `--accent` #C0B7FA. Акцент ТОЛЬКО на действии/бренде, ≤3 цветных пятна на экран.
- Деньги/суммы — белым, жирно, `tabular-nums` (класс `.num`). НИКОГДА не зелёным, никакого золота.
- Минимализм, понятно новичку, без крипто-жаргона в видимых текстах (никаких approve/allowance/gas/pending).
- Подсказки — максимум одна короткая строка на секцию (владелец ненавидит многословие).
- Никаких ссылок на несуществующие страницы, никаких выдуманных метрик.
- Экраны с сайдбаром: панель слева, колонка контента по центру (`margin: 0 auto`).
- Бренд-знак: `CheerBadge` — шестиугольник с короной-вырезом, режим `outline` для «пустого сосуда».

## Голосование

Вердикт по заданию и по сбору — единственная часть игры, которая принадлежит зрителям.
`components/games/VotePanel.tsx` показывает кнопки **только** пока канистра говорит `Voting`
(в закрытом окне голос всё равно отбили бы), а вес не заявляется, а доказывается: флоу тянет witness
из книги и игра его проходит. Голос бесплатный — ни комиссии, ни эскроу.

## Правила работы в этом репо

- **Один сервер, только localhost:3000.** Держателя порта искать `ss -ltnp | grep ':3000'`. Прод-сборки — в изолированный dist: `NEXT_DIST_DIR=".next-release" npx next build && NEXT_DIST_DIR=".next-release" npx next start -p 3000`.
- **Параллельные ИИ-агенты** правят это же дерево одновременно. Перед сборкой поллить tsc; чужие красные строки чинить минимально и только если блокируют; свои изменения перепроверять после «Note: file was modified».
- Git: `origin` = **github.com/Crown-protocol/Crown-App**, ветка main. Внутри репа всё переименовано в
  Cheer (`package.json`, ключи `cheer-*`, домен), адрес репа остался Crown — расхождение известное.
  Протокольные строки при этом **обязаны** оставаться `crown:*`: они подписываются и сверяются
  байт-в-байт (`crown:conditional-tasks:v1`, `crown:two-outcome:devnet`, `crown-chain:v1:`).
- Клон лежит рядом с периметром: `<workspace>/crown-app`, соседи — `crown-spec`, `crown-indexer`,
  `crown-factory`, `crown-splitter`, `crown-relay`, `crown-games`. Скрипты проверок их читают.
- В git НЕ входят: `data/` (БД), `.env.local`, `.next-*`, `bot/.env`, `bot/data`.
- Контакт проекта: **cheerdonate@proton.me** (футер лендинга).

## Известные ограничения (честные)

- Голос аукциона пишет мету целиком (replace) — два голоса в одну секунду из разных браузеров могут потерять один (перекаст после полла). Деньги через это не ходят.
- Стримерский `replace` списка (принять/удалить) теоретически может перетереть зрительский `append` в субсекундном окне.
- Донат деньгами в chain-режиме требует кошелёк-расширение (by design).
- Отказ подписать сохранение профиля при подключённом кошельке → серверная копия не обновится (localStorage сохранится); create-визард блокирует главный такой путь (ручной реальный адрес без кошелька — нельзя завершить).
- `serverPages` в DataProvider грузится раз за сессию — страница, зарегистрированная после загрузки вкладки зрителя, резолвится после его перезагрузки.
- Синк-операции игр не подписываются (уровень доверия мок-слоя игр); подписи охраняют профили/тексты/донаты.
- **Канистры публично не задеплоены** — принципалов в `ic` нет. Но локальный стенд есть и работает:
  `localnet/` (`dfx.json` + `deploy.sh`) поднимает индекс, релей, обе игры и мок SOL RPC на реплике
  `dfx`, а `crown-app/.env.local` привязывает фронт к ним. Периметр при этом **не правится**: всё
  локальное различие передаётся init-аргументами, которые эти канистры и так принимают (root key
  реплики, принципал индекса, allowlist релея). Мок SOL RPC деплоится по пиннутому принципалу
  (`--specified-id`), потому что этот адрес вшит в замороженный код.
  `localnet/feed-rpc.mjs <sig>` кладёт в мок **реальную** devnet-транзакцию, перекодировав её в
  candid-форму `parse.rs` (индекс просит base58 и только его декодирует), — так что сворачивается
  ровно то, что произвела Solana.
- Дедлайн эскроу считается клиентом, а не спрашивается: `now + duration + voting_period +
  DEADLINE_MARGIN + час запаса`. У сбора якорь другой — `created_at` первого вклада, и он читается из
  `get_collection`; догадка вместо чтения делает вклад возвратным раньше вердикта.
- Флоры (`MIN_GROSS_*`) и тайминги в `lib/chain/config.ts` — **devnet**. На mainnet-профилях они выше;
  выпустить mainnet-сборку со старыми числами значит принимать донаты, которые канистра откажется
  регистрировать уже после оплаты.
